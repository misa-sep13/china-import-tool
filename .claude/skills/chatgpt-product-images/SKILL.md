# ChatGPTで商品画像を作る

指示書と実物写真をもとに、ChatGPTで商品画像を枚数分作る。
仕上がりは文字・色だけでなく「物として正しく描けているか」まで確認する。崩れがあれば、ユーザーに聞く前にその場で修正指示を出す。

## 始める前に揃えるもの

- **画像作成指示書**：各画像で伝えること、入れる文字、変えてはいけない事実、NG。
- **実物写真**：1688の商品画像など。指示書と食い違う場合は写真を正とする。色・形・部品の位置を写真で確かめてから進める。
- **ChatGPTへのログイン**：Chromeでログインしておく。ログインはClaudeからはしない。無料プランは1日の生成枚数が少ないので、何枚も作るなら有料プランにする。
- **保存先**：`product_images/<商品名>_<日付>/` に番号付きで保存する（例：`01_6枚セット.png`）。

## 流れ

1. **指示書と写真を突き合わせる**
   - 写真と指示書の食い違い（色・サイズ・部品の材質など）を洗い出す。1688のページで規格（SKU）一覧も確認する。
   - 指示書が「未確認」にしている仕様は画像の文字に使わない。ユーザーが「使う」と決めたら、出所（1688の記載で自社では未実測、など）を伝えたうえで使う。
   - 食い違いはユーザーに確認してから生成する。
2. **構成を決める**
   - 1枚ごとに構図を変える。同じ構図（ボード正面＋丸い拡大写真、手で書いている姿、など）が2枚以上にならないようにする。
   - 構成表（何枚目に何を見せ、どんな構図で、どの文字を入れるか）をユーザーに見せて了承をもらう。
3. **この商品の確認リストを作る**（下の「確認すること」の商品別の部分）。
4. **生成する**：Claude in Chromeで、ChatGPTのタブを枚数分開く。各タブに実物写真を添付し、下の型で指示を送る。
5. **確認する**：1枚ずつ拡大して確認する。2案を出されたら、同じ基準で選ぶ。
6. **直す**：直し方は下の「直らないときの手」の順に試す。
7. **保存する**：ビューアを開き、ダウンロードボタンで保存する（シリーズ画像はメニューから「画像をダウンロード」を選ぶ）。保存先に番号付きのファイル名で移す。保存したファイルを開いて、修正後の版か確認する。

## 指示の型

毎回、全タブで同じ共通部分を先頭に入れる。

- Amazon・楽天用の商品画像を1枚、正方形1:1で生成する。
- 添付は実物写真であること。写真内の中国語・ラベル・ロゴ・数字は商品ではないので無視し、形・色・質感だけを参考にすること。
- **トーン**：指示書の色指定をそのまま書く。
- **守ること**：
  - 本体と部品の色
  - サイズとタテ・ヨコの向き
  - 実在しない付属品を足さない
  - 未確認の数値を書かない
  - 未検証の性能（反らない・割れない・防水など）を書かず、示唆もしない
  - 顔を入れない
  - 指定した日本語以外の文字を入れない
- **この画像で伝えること**：構図は具体的に書く。カメラの位置、物の向き、手の位置まで書く。
- **入れる文字**：指示書の★の案を使う。

## 確認すること

### どの商品でも見る

1. **形が実物どおりか**：歪み、縦横の比率、数（「6枚セット」なら6個あるか）。
2. **部品の位置と色が実物写真どおりか**：付いている場所、向き、色の組み合わせ。
3. **物どうしの重なりが正しいか**：何が上で何が下か。挟まる・入る・差し込まれる関係が成立しているか。余計な層やはみ出しがないか。
4. **使っている人の動きが自然か**：画面・紙・表示が使う人の方を向いているか。手や指が物理的にありえる位置か。人に対するサイズは自然か。
5. **見えてはいけないものが出ていないか**：実在しない付属品、実物にない文字、使用中なら隠れるはずの部品。
6. **文字と数値が指示書どおりか**：指定していない言葉や数値が足されていないか。日本語が崩れていないか。写真の数字（例：310mm）を写していないか。

### 商品ごとに作る

生成の前に、指示書と写真からその商品で崩れやすい点を3〜5個書き出し、上の6項目と一緒に確認する。

例：クリップボードの場合
- 紙がボードの表面に1枚だけ置かれているか
- 紙の上端がクリップの押さえ板の下に入り込んでいるか
- 紙を奥まで差し込んだ状態で、クリップの土台とねじが紙で隠れているか
- 書いている人から紙が見える向きか

例：TODO付箋の場合
- 印刷の行数とボックスの数が実物どおりか（帯が1本多い・少ないが一番起きやすい）
- 見出しの行（Date:など）に帯が入り込んでいないか、ボックスと帯の段がそろっているか
- 画像全体で冊数がセット数どおりか（参考写真の冊数や、背景に足された束を数え漏らさない）
- 下に重ねた冊が色の塊になっていないか（紙は白で、色は印刷部分だけ）

**数えられるものは数える。** 冊数・行数・ボックスの数・帯の本数は、拡大して1つずつ数える。見た目の印象では見逃す。

## 直らないときの手

1. **同じチャットで、具体的に直させる**：何がどうおかしいか、どうあるべきかを番号付きで書く。
2. **新しいチャットで作り直す**：同じチャットでは前の画像に引きずられ、構図が変わらないことが多い。新しいチャットでは、実物写真だけを渡して一から作らせる。
3. **見本写真を一緒に渡す**：「挟まり方」「持ち方」など言葉で伝わらないものは、それが写っている写真を「この部分だけ真似る」と明記して添付する。
4. **直接加工する**：ねじを消す、紙を少し伸ばすなどの小さな修正は、Pillowで隣の模様を貼るか、範囲を塗る。加工前のファイルを残し、元画像との差分の範囲を確かめて、ほかの部分が変わっていないことを確認する。

## 気をつけること

- ChatGPTの「ファイルはチャットにのみ追加されました」という表示は、×で閉じてから入力欄に入力する。
- 一度に多くのタブを操作すると、ブラウザとの接続が切れることがある。切れたら各タブの状態を確認し、送れていないタブだけ送り直す。
- 1688のページは別のタブに出たり、読み込みに時間がかかったりする。開けなければユーザーに伝える。
- 「1688検索」のオレンジのボタンはChrome拡張の表示で、画像には入っていない。
- **画像はフル解像度で確認する**：画面のプレビューは小さく、行数のずれや冊数の間違いを見逃す。各タブで次のJavaScriptを実行すると、最新の画像を名前付きでダウンロードできる（ビューアを開いてボタンを押すより確実で速い）。落としたファイルを開いて確認する。
  ```js
  (async () => { const imgs=[...document.querySelectorAll('img')].filter(i=>i.naturalWidth>=512); const img=imgs[imgs.length-1]; const blob=await (await fetch(img.src)).blob(); const a=document.createElement('a'); a.href=URL.createObjectURL(blob); a.download='名前.png'; document.body.appendChild(a); a.click(); a.remove(); })()
  ```
  生成中に実行すると、前の画像や添付写真を落とすことがある。前の版と同じファイルになっていないか比べる。
- **修正指示が送れたか確かめる**：画像ビューアが開いたまま入力すると、チャット欄ではなくビューアの「編集内容を入力」に入り、送れていないことがある。入力欄は座標ではなく find で「ChatGPT に聞く」を探してクリックし、送信後に自分のメッセージが表示されたか確認する。
- 同じ修正を2回頼んでも変わらないときは、それ以上同じチャットで粘らず、新しいチャットで作り直すか直接加工する。
