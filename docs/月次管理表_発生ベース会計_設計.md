# 月次管理表（発生ベース会計）設計

作成：2026-11-17　状態：**設計のみ。実装は未着手**

---

## 1. 何を解決したいか

いまの試算表は、**タオタロウにデポジットした日**で仕入が計上されている。
デポジットは「まとめて入金する前払金」であって、その月に仕入れたものではない。
そのため月ごとに利益の見え方が大きく振れる。

> 例：11/5に30万円チャージ → 11月の原価が30万円増える。
> その30万円で実際に買った商品が12月に届いて1月に売れても、原価は11月に立っている。

**これを、その月に実際に発生したものだけを拾う形（発生ベース）に組み替える。**

あわせて、いま暫定で入っている数字（送料はツール登録値、店舗別内訳書なし）を
実額に置き換え、根拠書類も同じ場所から税理士がダウンロードできるようにする。

## 3. 発生日をどう決めるか

候補は「輸入許可日」と「商品の到着日」。

**輸入許可日を採用する。** 理由は単純で、**到着日の実データが無い**（`import_permits.arrival_date`
は41件すべて空）。輸入許可日は41件すべて入っている。
実務上も両者は数日しか違わないので、月次の利益の見え方はほとんど変わらない。

- 商品代・調整 → 注文日
- 送料・手数料 → 便の出荷日
- 関税・消費税 → 輸入許可日
- 月会費 → 毎月1日（按分しない）
- チャージ → 計上しない（前払金の増減）

## 5. 画面の形

- 楽天とAmazonを**同じ場所**に置く（別タブでよい）
- 月を選ぶと、その月の発生ベースの損益が出る
- デポジットの内訳（商品代・中国国内送料・代行手数料・国際送料・通関料・月会費・チャージ）を分解して見せる
- 在庫金額を併記（`inventory_snapshots` に月末在庫を持つ仕組みは既にある）
- 根拠書類はその月の行からダウンロードできる

### マネーフォワードとの関係

- 税理士は**この管理表を直接見る**。入力は税理士が行う
- MFに自動連携している明細（埼玉りそなの国際送料引き落としなど）を**ツール側に取り込む**
- 取り込み方：**CSVは確実**。API連携も可能だが、**使える範囲は未確認**
